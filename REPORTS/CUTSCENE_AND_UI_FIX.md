# 컷씬 자막 및 UI 수정 보고

## 원인

- BSCR 대사 문자열은 Shift-JIS가 아니라 UTF-8 기반으로 해석해야 했다.
- 이전 구현은 문자열 참조 테이블을 16바이트 슬롯 위상으로 가정해 일부
  포인터를 놓쳤고, 그 결과 컷씬에서 `@@@@`가 표시되거나 자막이 누락됐다.
- 메뉴 텍스트 갈라짐은 PTMD 스위즐이 아니라 UI 폴백 생성기의 좁은 배치와
  여백 부족에서 발생했다.

## 수정

- BSCR에는 `glyph_alias_map_bscr_cjk.json` 기반 UTF-8 CJK 별칭 인코딩을
  적용했다.
- 문자열 풀 뒤쪽을 4바이트 정렬 단위로 검사하고, 값이 기존 문자열 시작점과
  정확히 일치하며 뒤 8바이트가 `5A`인 참조만 인식했다.
- 이동된 문자열 참조 `37,139 / 37,139`개를 재배치하고, 모든 인식 포인터가
  새 문자열 시작점을 가리키는지 재검증했다.
- 27개 PTMD의 100개 그래픽 UI 라벨을 다시 배치했고, 렌더링 잉크가 경계를
  건드리면 빌드가 실패하도록 여백 검사를 추가했다.
- 최종 ISO에는 UI가 포함된 게임 컨테이너 9개를 직접 내장했다.

## 검증

- 최종 ISO SHA-256:
  `554b67aff4fc0fd95ad50a2ac5f470192a40d0b868cdc2f5bbfd2e2ad4f5b313`
- PPSSPP STG04 컷씬에서 한국어 자막 두 문장을 직접 확인했다.
- 컷씬에서 `@@@@`가 나타나지 않음을 확인했다.
- 스테이지 선택 화면의 한국어 UI를 직접 확인했다.
- 런타임 오류 수: `0`

스크린샷 증거는 `REPORTS/ppsspp_evidence`에 포함되어 있다.

## 메뉴 갈라짐 2차 수정

첫 수정은 텍스처 전체 그림만 검사해 게임이 라벨별로 잘라 쓰는 UV 영역을
침범했다. PPSSPP 실기 화면을 통해 `IF_STAGE_SELECT/014`의 실제 원본
알파 행을 다음과 같이 다시 측정했다.

- 제목: `y=0..9`
- 저장/헌트: `y=11..20`
- 로드/추가: `y=22..31`
- 메뉴/스토리: `y=32..41`
- 보조 라벨: `y=43..47`

각 행을 이동하지 않고 Galmuri 픽셀 한글을 1비트로 렌더했으며, 보조 영문
라벨과 아이콘은 원본 픽셀을 보존했다. PPSSPP에서 `저장`, `로드`, `메뉴`가
한 줄씩 표시되고 인접 라벨 조각이 섞이지 않는 것을 다시 확인했다.

## 필드 ★MENU 라벨 유지 결정

필드 `★MENU`의 `CUSTOMIZE / ITEMS / CHALLENGES / OPTIONS / EXP / NEXT /
LEVEL`은 여러 고정 UV 조각을 조합하는 별도 초소형 아틀라스다. 한글판을
시험 빌드해 PPSSPP에서 확인했으나 글자가 잘리고 인접 조각과 섞였다.
가독성을 우선한다는 최종 결정에 따라 이 라벨들은 원문 영문을 유지하고,
해당 시험 패치는 ISO와 배포 패키지에서 완전히 제거했다.
